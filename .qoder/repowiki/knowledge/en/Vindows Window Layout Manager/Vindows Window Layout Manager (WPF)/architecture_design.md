Single WinExe WPF project targeting net10.0-windows with `UseWPF=true`. The UI layer (`App.xaml.cs`, `MainWindow.xaml.cs`, `ZoneVM.cs`) owns the live state: monitor list, layouts, and window enumeration. All platform interaction is isolated in `Core/Win32.cs` via `DllImport` declarations to `user32.dll` and `dwmapi.dll` for monitor enumeration (`EnumDisplayMonitors`, `GetMonitorInfo`), window enumeration (`EnumWindows`, `GetWindowText`, `GetWindowThreadProcessId`), and placement (`SetWindowPos`, `ShowWindow`). `Core/WindowEnumerator.cs` wraps the Win32 calls into a filtered `List<WindowInfo>` of visible top-level windows. `Core/LayoutApplier.cs` is the pure layout engine: it builds percentage-based `Zone` grids from columns/rows/gap, converts zones to pixel rects, and moves matching process windows onto monitors. `Core/LayoutStore.cs` persists layouts as JSON under `%APPDATA%\Vindows\layout.json` using `System.Text.Json`. `Core/Models.cs` defines the shared data contracts (`MonitorInfo`, `Zone`, `MonitorLayout`, `WindowInfo`, `LayoutFile`) consumed by both UI and Core. Dependency direction is strictly UI → Core; Core has no WPF dependencies beyond `System.Windows.Rect`.
